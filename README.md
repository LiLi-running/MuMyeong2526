# 무명의 유산

화면은 **GitHub Pages**, 로그인·데이터·전투 판정은 **Supabase**(무료)에서 동작합니다.
전투 주사위, 출석 시간, 운세, 구매, 과제 보상 등 실타래가 오가는 모든 판정은 서버 함수가 처리하므로 화면 코드를 고쳐도 결과를 조작할 수 없습니다.

---

## 1. Supabase 준비 (약 10분)

1. https://supabase.com 가입 → **New project**
   - Region: **Northeast Asia (Seoul)**
   - Database password는 따로 잘 보관하세요.
2. 왼쪽 메뉴 **SQL Editor** → New query
   - `supabase/` 폴더의 파일을 **번호 순서대로** 하나씩 붙여 넣고 **Run**
     `01_schema` → `02_battle_functions` → `03_team_passives` → `04_features` → `05_storage`

> **이미 01~03을 실행했다면:** `04_features.sql` → `05_storage.sql` 만 실행하면 됩니다.
> 모든 SQL 파일은 여러 번 다시 실행해도 안전합니다. 규칙이 바뀌면 바뀐 파일만 다시 실행하세요.
> (단, 02를 다시 실행했다면 04도 이어서 다시 실행해 주세요.)
3. **Authentication → Sign In / Providers**
   - 아래쪽 공급자 목록에서 **Email**을 눌러 **Enable email provider** 켜기 → Save
     (꺼져 있으면 아이디·비밀번호 로그인이 안 됩니다. 패널 안의 다른 항목은 기본값 그대로)
   - 페이지 위쪽 **User Signups** 영역에서:
     - **Allow new users to sign up** 끄기 ← 중요! 아무나 계정을 만들지 못하게 합니다.
     - **Confirm email** 끄기 (가상 이메일을 쓰기 때문)
   - Save
4. **Project Settings → API** (또는 API Keys)
   - `Project URL` 과 `anon public`(또는 `publishable`) 키를 복사해 `js/config.js` 에 붙여 넣기
   - `service_role` / `secret` 키는 **절대** 넣지 마세요.

## 2. 관리자 계정 만들기

1. **Authentication → Users → Add user → Create new user**
   - Email: `admin@nameless.legacy` (아이디가 `admin`이 됩니다)
   - Password 입력, **Auto Confirm User** 체크
2. SQL Editor에서 실행:
   ```sql
   update public.profiles set is_admin = true where login_id = 'admin';
   ```

참여자 계정도 같은 방법(`아이디@nameless.legacy`)으로 만들면 됩니다.
비밀번호를 잊은 참여자는 관리자 페이지 › 캐릭터 › **비밀번호** 버튼으로 새 비밀번호를 지정해 줄 수 있습니다.

## 3. GitHub Pages에 올리기

1. GitHub에서 새 저장소 만들기 (예: `nameless-legacy`)
2. 이 폴더의 파일을 전부 업로드 (**Add file → Upload files**, 폴더 구조 그대로, **한 번에** 올리고 한 번만 Commit)
3. 저장소 **Settings → Pages → Branch: main / (root) → Save**
4. 1~2분 뒤 `https://<깃허브아이디>.github.io/nameless-legacy/` 에서 열립니다.

나중에 주소를 바꾸려면 같은 화면의 **Custom domain**에 도메인을 입력하고, 도메인 DNS에 CNAME을 추가하면 됩니다.
(`legacy.endofverdant.xyz` 같은 서브도메인도 가능합니다.)

## 4. 업데이트할 때

- 받은 파일을 **한 번에** 올리고 한 번만 Commit 하세요. 나눠 올리면 앞의 배포가 취소될 수 있습니다.
- 저장소 **Actions** 탭에서 배포가 초록색 체크로 끝난 뒤 **Ctrl + Shift + R** 로 새로고침하세요.
- `js/config.js` 는 직접 입력한 키가 들어 있으므로, 업데이트 파일에 없으면 그대로 두면 됩니다.
- 파일 버전이 섞이면 빈 화면 대신 "페이지를 불러오지 못했습니다" 안내가 뜹니다.

## 5. 테스트 순서

1. `admin` 으로 로그인 → 주소창에 `admin.html` 직접 입력
2. **캐릭터** 탭: 테스트 계정들의 이름 · 팀 · 포지션 지정 후 저장 (팀 이름은 직접 입력)
3. **전투** 탭: 방 선택 → 양쪽 팀과 파티원 체크 → 전투방 만들기 → 시작
4. 다른 브라우저(또는 시크릿 창)로 참가자 계정에 로그인 → **차원의 틈** → 입장
5. 모두 결정하면 자동으로 라운드가 진행됩니다. 누군가 자리를 비우면 관리자가 **라운드 강제 진행**.

```
index.html          메인 (달력 · 로그인 · 바로가기)

attendance.html     출석
fortune.html        운세
shop.html           상점 · 선물
tasks.html          과제 (상시: 별 잡기 / 기간: 글+그림 제출)
battle.html         차원의 틈
characters.html     명단
me.html             내 캐릭터 · 비밀번호 변경
admin.html          관리자 페이지 (메뉴에 링크 없음)
css/style.css       디자인 (#e5e7e4 / #3c3f42)
js/config.js        ★ Supabase 주소·키, 트위터·신청서 링크
js/supabase.js      로그인 · 공통 함수 · 팀 패시브 표시 문구
js/ui.js            마크다운 · 이미지 업로드 · 창 · 날짜
js/layout.js        왼쪽 고정 메뉴 (메뉴 항목 수정은 여기서)
js/guard.js         파일 버전이 섞였을 때 안내 표시
js/*.js             각 페이지 화면
supabase/01~05      서버 (테이블 · 권한 · 판정 함수 · 이미지 저장소)
```

## 관리자 페이지 보안

`admin.html` 주소를 누가 알아내도 괜찮습니다. 관리자 기능은 모두 서버 함수에서 `is_admin`을 확인하므로, 일반 계정은 화면만 보이고 어떤 데이터도 바꿀 수 없습니다.
그래도 주소를 숨기고 싶다면 `admin.html` 파일 이름을 아무거나(예: `keeper-7x2.html`)로 바꾸면 됩니다.

## 규칙 해석 (원문에서 정해지지 않아 임의로 정한 부분)

바꾸고 싶은 항목은 알려 주시면 SQL 한두 줄로 조정할 수 있습니다.

| 항목 | 현재 동작 |
|---|---|
| 속도 투자 | 파티원 결정 순서대로 남은 속도에서 차감. 0도 가능. 남은 속도를 넘으면 서버가 거부 |
| 결정 변경 | 한 번 결정하면 그 라운드에는 변경 불가 |
| 동일 속도 | 자명고 우선, 그 외에는 무작위 순서 |
| 강타 | 11~20 + 10 = 21~30 피해 |
| 크리티컬 | 모든 행동(증진 포함) 10%, 수치 × 1.5 (소수점 버림). 팀 패시브 우선 |
| 증진 | 대상의 **다음 행동**에 +10. 이번 라운드에 이미 행동했다면 다음 라운드로 넘어감. **크리티컬 적용 전에 더함** (예: 공격 15 + 증진 10 → 크리 시 37) |
| 보호 | 다음 1회 피격을 11~20 상쇄 후 소멸. 이번 라운드에 맞지 않으면 다음 라운드 끝까지 유지 |
| 치유 | 최대 체력 200을 넘지 않음. 쓰러진 캐릭터는 회복 불가 |
| 쓰러진 대상 | 행동 순서가 왔을 때 대상이 이미 쓰러졌으면 그 행동은 무효 |
| 미결정 | 관리자가 강제 진행하면 '행동 없음(속도 0)' |
| 승패 | ① 쓰러진 파티원이 없는 쪽 우선 → ② 같으면 체력 감소량이 적은 쪽 → ③ 그래도 같으면 무승부 |
| 성약 스킬 | 선택은 가능, 효과는 로그만 남김 (추후 `02_battle_functions.sql`의 `TODO` 위치에 추가) |
| 파티 인원 | 정식 규칙은 2~3명이지만, 테스트를 위해 1명부터 허용 |
| 관전 | 로그인한 누구나 전투 로그·체력 관전 가능. 채팅은 참가자만. 관리자는 양쪽 파티 채팅까지 열람 |

## 팀 패시브

팀은 관리자 페이지 › 캐릭터에서 이름으로 지정합니다. 아래 세 팀은 **이름이 정확히 같아야** 패시브가 적용됩니다.

| 팀 | 패시브 |
|---|---|
| 자명고 | 파티 속도 시작치 120. 같은 속도일 때 먼저 행동 |
| 이글 | 크리티컬 확률 15%. 크리티컬 시 공격·강타는 × 2 (그 외 스킬은 × 1.5) |
| 아타락시아 | 크리티컬이 터지면 행동한 캐릭터 체력 10 회복 (최대 200) |
| 그 외 | 패시브 없음 |

- 패시브는 **전투방을 만들 때 지정한 파티의 팀** 기준입니다.
- 팀 이름을 바꾸거나 패시브를 추가하려면 `02_battle_functions.sql`(실제 효과)과 `js/supabase.js`의 `TEAM_PASSIVES`(화면 표시)를 함께 고칩니다.

## 재난대비성약자양성소 규칙

실타래 증감은 모두 **실타래 기록**(장부)에 남습니다. 내 캐릭터에서 본인 기록을, 관리자 페이지에서 전체 기록을 볼 수 있습니다.

| 기능 | 현재 동작 |
|---|---|
| 출석 | 한국 시간 06:00 ~ 20:00, 하루 1번, 실타래 10. 시간은 서버 시계 기준 (내 컴퓨터 시계를 바꿔도 소용없음) |
| 운세 | 하루 1번 (자정 기준). 확률: 0개 10% · 1개 20% · 2개 25% · 3개 22% · 4개 15% · 5개 8% (평균 약 2.4개) |
| 상점 | 실타래로 구매. 받는 사람을 지정하면 바로 선물. 보유 아이템도 선물 가능 (메시지 200자) |
| 별 잡기 | 30초, 별 50개 (밝은 별은 3점). **10점당 실타래 1, 최대 5**. 보상은 **하루 3판까지** (점수와 무관하게 판 수로 셈), 그 뒤로는 기록만 남음. 순위표는 개인 최고 기록 |
| 기간 과제 | 기간 안에 글 + 그림 1장 제출. 마감 전까지 수정 가능. 실타래 보상은 **첫 제출 때 한 번** |
| 그림 업로드 | PNG · JPG · GIF · WEBP, 5MB까지. 각자 자기 폴더에만 올릴 수 있음 |
| 명단 | 관리자 계정은 명단에 나오지 않음. 사진 · 한마디 · 소개는 관리자 › 캐릭터 › **명단 카드**에서 입력 |
| 안내글 | 메뉴를 누르면 목록 없이 글 1개가 바로 보임. 로그인 없이 누구나 열람. 공개를 끄면 "아직 등록된 내용이 없습니다"로 표시 |

별 잡기는 브라우저에서 돌아가는 게임이라 완벽한 조작 방지는 불가능합니다. 대신 별 배치를 서버가 정하고, 제출된 클릭이 **그 별이 실제로 떠 있던 시간**인지 서버가 하나하나 검사합니다. 시간을 지어내거나 30초 전에 제출하는 것은 막히고, 보상도 하루 15개가 상한입니다. 이상한 기록은 관리자 › 과제에서 삭제할 수 있습니다.

## 관리자 페이지 기능

| 탭 | 할 수 있는 일 |
|---|---|
| 캐릭터 | 이름 · 팀 · 포지션 · 실타래 · 관리자 지정, 명단 카드, 비밀번호 재설정, 여러 명에게 실타래 일괄 지급 |
| 안내글 | 공지사항 · 세계관 · 캐릭터 가이드 · 시스템을 **메뉴마다 글 1개**로 작성 (글 · 표 · 그림, 미리보기, 공개/비공개) |
| 상점 | 아이템 추가 · 수정 · 숨김 (가격 · 재고 · 이미지), 캐릭터 보유 아이템 조정 |
| 과제 | 기간 과제 등록 · 수정, 제출물 열람, 별 잡기 순위 · 기록 삭제 |
| 실타래 기록 | 전체 / 캐릭터별 실타래 증감 내역 |
| 전투 · 일정 | 기존과 같음 |
